# JSON schemas

This directory holds JSON schemas for the project's JSON formats. Settings validation is the initial implementation scope, tracked in [the browser settings plan](../plans/browser-settings.md#milestone-3-implement-validation-and-recovery). A future `seed-data.json` schema for saved seed records belongs here too.

The settings schemas use JSON Schema Draft 2020-12. [settings/generation.json](settings/generation.json) describes complete generation values after preset resolution and references [settings/skill.json](settings/skill.json) for skill assumptions. Small subordinate structures are inlined. [settings/customization.json](settings/customization.json) describes the customization settings applied while patching.

For settings, Rust structs and schemas are maintained separately. Catalog preparation validates resolved preset JSON before converting it into Rust settings, so unknown authored fields remain visible to validation. Fixed Rust settings structs also reject unknown fields during Serde deserialization. Fixed objects reject additional properties and require fields guaranteed by resolution. Data-driven maps describe their values generically; Rust semantic verification checks member identities, permitted proficiency levels, and item-specific minimums using prepared data. Specific technique, room, notable, and item IDs do not belong in the settings schemas.

The schemas' `urn:z3-map-rando:schema:settings:*` identifiers name resources for an in-memory registry; they are not retrieval addresses. The shared Rust processor embeds both resources and compiles one reusable `jsonschema` validator with default retrieval features disabled and offline construction. Native and browser builds use the same resources without schema-fetch requests. Schema contents participate in catalog invalidation. The built-in-preset consistency test resolves each root and root/skill combination, validates it, and deserializes it without notices or errors.
